# مُحيِّد — دليل الاختبار

يعمل النظام في ثلاث حاويات Docker:

| الحاوية | الوصف | العنوان |
|---|---|---|
| `frontend` | تطبيق ويب React (PWA) يقدّمه nginx | http://localhost:8081 |
| `backend` | واجهة برمجية NestJS | http://localhost:3000 |
| `db` | قاعدة بيانات PostgreSQL 17 (البيانات في وحدة تخزين Docker) | `127.0.0.1:5434` |

## ٢. ما الذي تحتاجه

- برنامج **Docker Desktop** مثبّتاً و**قيد التشغيل** (ويندوز أو ماك أو لينكس). للتحقق: الأمران `docker --version` و`docker compose version` يطبعان رقم الإصدار.
- **اتصال بالإنترنت عند البناء الأول** (لتنزيل الصور والحزم).
- يُفضَّل متصفح مبني على Chromium (Chrome أو Edge أو Brave) لاختبار العمل دون اتصال.
- المنافذ التالية فارغة على جهازك: **8080** و**3000** و**5434** (راجع «حل المشكلات» إن لم تكن فارغة).

## ٣. تشغيل النظام

فُكَّ ضغط الحزمة، ثم افتح الطرفية (Terminal) **داخل مجلد المشروع** (المجلد الذي فيه الملف `docker-compose.yml`). في ويندوز: انقر بزر الفأرة الأيمن على المجلد ثم **Open in Terminal**.

**الخطوة ١. بناء الصور وتشغيل الحاويات** (في المرة الأولى تستغرق عدة دقائق)

```bash
docker compose up -d --build
```

**الخطوة ٢. تأكد أن كل شيء سليم**

```bash
docker compose ps
```

يجب أن تظهر `db` و`backend` و`frontend` بالحالة **healthy** (قد يستغرق ذلك دقيقة؛ أعد الأمر إن ظهرت `starting`).

**الخطوة ٣. إنشاء جداول قاعدة البيانات** (خطوة يدوية، تُنفَّذ مرة واحدة، وتُعاد بعد تحديث الشيفرة)

```bash
docker compose run --rm tools npm run db:migrate
```

آخر سطر متوقع: `migrations applied successfully!`

**الخطوة ٤. إنشاء حساب المسؤول الأول** (مرة واحدة)

```bash
docker compose run --rm tools npm run db:seed
```

المتوقع: `Admin created: admin@muhaid.local`

> الخطوتان ٣ و٤ يدويتان عن قصد: لا شيء يغيّر قاعدة البيانات ما لم تنفّذه بنفسك. قبل إتمام الخطوة ٣ يردّ التطبيق بأخطاء.

**الخطوة ٥. افتح التطبيق** على العنوان **http://localhost:8081**

> استخدم العنوان `localhost` كما هو مكتوب بالضبط. استخدام `127.0.0.1` أو عنوان IP الجهاز يجعل المتصفح يمنع طلبات الواجهة البرمجية.

يبدأ التطبيق بالعربية. اضغط **English** (في الزاوية العلوية) لتبديل اللغة، واضغط **العربية** للعودة.

## ٤. الحسابات

| الدور | البريد الإلكتروني | كلمة المرور |
|---|---|---|
| المسؤول (جاهز بعد الخطوة ٤) | `admin@muhaid.local` | `Admin_12345` |
| المفتش (تنشئه في القسم ٥) | `inspector@muhaid.local` | `Inspector_123` |

قاعدة البيانات (اختياري، لأداة مثل TablePlus): المضيف `127.0.0.1`، المنفذ `5434`، المستخدم `postgres`، كلمة المرور `muhaid_demo_2026`، القاعدة `muhaid`.

## ٥. تجهيز بيانات الاختبار (بصفة المسؤول، نحو ٥ دقائق)

سجّل الدخول بحساب المسؤول. في القائمة الجانبية: **التفتيشات** و**المشاريع** و**النماذج** و**المستخدمون**.

1. **إنشاء مفتش.** **المستخدمون** ← **إضافة مستخدم**. املأ: الاسم `Test Inspector`، البريد الإلكتروني `inspector@muhaid.local`، كلمة المرور `Inspector_123`، الدور `مفتش`. اضغط **إنشاء المستخدم**.
2. **إنشاء مشروع.** **المشاريع** ← **مشروع جديد**. رمز المشروع `DEMO-001`، اسم المشروع `Demo Tower`. اضغط **إنشاء المشروع**.
3. **إنشاء نموذج (نموذج التفتيش).** **النماذج** ← **نموذج جديد**.
   - المشروع: ابحث عن `DEMO` واختر `DEMO-001`.
   - اسم النموذج: `Daily Safety Check`.
   - صالح من: **تاريخ اليوم**. حدّد **بلا تاريخ انتهاء**.
   - الأسئلة: اكتب السؤال الأول، ثم اضغط **إضافة سؤال** لكل سؤال تالٍ. مثال:
     1. `هل يرتدي العمال معدات الحماية؟`
     2. `هل منطقة العمل مسيّجة؟`
     3. `هل طفايات الحريق في أماكنها؟`
   - اضغط **إنشاء النموذج**.
4. **تعيين المفتش.** في صفحة النموذج اضغط **تعيين مفتشين**، حدّد `Test Inspector`، ثم اضغط **تعيين مفتش واحد**. يُولَّد رقم أمر عمل تلقائياً (مثل `WO-000001`).

> لا يرى أحد النموذج قبل تعيينه. وإذا كان تاريخ «صالح من» في المستقبل فلا يستطيع المفتش تعبئته.

عند الانتهاء سجّل الخروج (الأيقونة في الزاوية العلوية).

## ٦. اختبار تطبيق المفتش والعمل دون اتصال

### ٦.١ تسجيل الدخول وتحميل النماذج (باتصال)

1. سجّل الدخول بالحساب `inspector@muhaid.local` / `Inspector_123`. تصل إلى **النماذج** (**النماذج المعيّنة**) وترى `Daily Safety Check`.
2. **ابقَ متصلاً بضع ثوانٍ** ليُخزَّن التطبيق والنماذج على الجهاز. للتحقق (اختياري): اضغط `F12` ← **Application** ← **Service Workers**؛ يجب أن تظهر الحالة *activated and is running*.

### ٦.٢ الاختبار أ: العمل دون اتصال وتعبئة نموذج

1. اضغط `F12` ← تبويب **Network** ← من قائمة التحكم بالسرعة اختر **Offline**.
2. يظهر شريط التنبيه: *لا يوجد اتصال. ما تحفظه يبقى على هذا الجهاز ويُرسل عند توفر الاتصال.*
3. اضغط `F5` لإعادة تحميل الصفحة. **يفتح التطبيق رغم ذلك** وتبقى قائمة النماذج ظاهرة.
4. افتح `Daily Safety Check`. أجب عن كل سؤال (**نعم** أو **لا** أو **لا ينطبق**). كل إجابة **لا** تتطلب ملاحظة.
5. في حقل صورة التفتيش اضغط **التقاط صورة** واختر الملف **`sample-photo.jpg`** من مجلد الحزمة (JPEG أو PNG أو WebP، حتى 5 م.ب).
6. اضغط **حفظ التفتيش**. تظهر الرسالة *حُفظ التفتيش على هذا الجهاز*.
7. افتح **الصادر**. يظهر `تفتيش واحد في الانتظار`.
8. أعد خيار السرعة إلى **No throttling**. يُرسل الصادر تلقائياً؛ وإن لم يحدث شيء خلال دقيقة فاضغط **إرسال الآن**.
9. افتح **المُرسل**: يظهر التفتيش مع رقم أمر العمل وحالة المزامنة (**في وقته**، أو *أُرسل بعد …* لأنه انتظر دون اتصال).

### ٦.٣ الاختبار ب: إيقاف الخادم فعلياً

هذا أقوى من مفتاح Offline في المتصفح، لأن الخوادم نفسها تتوقف.

1. أبقِ المفتش مسجّلاً الدخول والتطبيق مفتوحاً. في الطرفية نفّذ:

   ```bash
   docker compose stop frontend backend
   ```

2. أعد تحميل الصفحة (`F5`). **يبقى التطبيق يعمل**، لأن المتصفح يحتفظ بنسخته الخاصة (service worker) رغم توقف خادم الويب.
3. عبّئ نموذجاً آخر واحفظه كما في الاختبار أ. يذهب إلى **الصادر**.
4. شغّل الخوادم من جديد:

   ```bash
   docker compose start backend frontend
   ```

5. انتظر نحو دقيقة (أو اضغط **إرسال الآن** في الصادر). ينتقل التفتيش إلى **المُرسل**.

> يجب أن يكون التطبيق قد فُتح مرة واحدة على الأقل وهو متصل (٦.١). المتصفح الذي لم يحمّله من قبل لا يستطيع فتحه دون اتصال.

### ٦.٤ مراجعة النتيجة بصفة المسؤول

سجّل الخروج، ثم سجّل الدخول بحساب `admin@muhaid.local`، وافتح **التفتيشات**. ستجد التفتيشات التي أرسلتها. افتح أحدها لترى الإجابات والملاحظات والصورة.

## ٧. أوامر يومية

| الهدف | الأمر |
|---|---|
| الحالة | `docker compose ps` |
| السجلات | `docker compose logs -f backend` |
| الإيقاف (مع الاحتفاظ بالبيانات) | `docker compose stop` |
| التشغيل من جديد | `docker compose start` |
| إزالة الحاويات (مع الاحتفاظ بالبيانات) | `docker compose down` |
| **حذف كل شيء بما فيه البيانات** | `docker compose down -v` (ثم أعد الخطوات ١ و٣ و٤) |

## ٨. حل المشكلات

| المشكلة | الحل |
|---|---|
| `port is already allocated` | برنامج آخر يستخدم 8080 أو 3000 أو 5434. عدّل الملف `.env`: غيّر `FRONTEND_HOST_PORT` (وغيّر `CORS_ORIGIN` ليطابقه)، أو `BACKEND_HOST_PORT` (وغيّر `VITE_API_URL` ليطابقه)، أو `DB_HOST_PORT`. مثال: `FRONTEND_HOST_PORT=8090` و`CORS_ORIGIN=http://localhost:8090`. ثم نفّذ `docker compose up -d --build` وافتح العنوان الجديد. |
| فشل تسجيل الدخول أو ظهور أخطاء الخادم | لم تُنفَّذ الخطوة ٣ (الترحيل) أو الخطوة ٤ (إنشاء المسؤول). نفّذهما. |
| ظهور خطأ **CORS** في وحدة تحكم المتصفح | فتحت التطبيق عبر `127.0.0.1` أو عنوان IP، أو أن `CORS_ORIGIN` لا يطابق العنوان في شريط المتصفح. |
| غيّرت منفذاً لكن التطبيق ما زال يستدعي عنوان الواجهة القديم | `VITE_API_URL` يُدمج داخل الواجهة وقت البناء. نفّذ `docker compose up -d --build` من جديد. |
| ما زالت الشاشة القديمة تظهر بعد تحديث | أغلق كل تبويبات التطبيق ثم افتحه من جديد (التحديث ينتظر إغلاق التبويبات). |
| `docker: command not found` أو أخطاء Docker | شغّل Docker Desktop وانتظر حتى يعلن أنه يعمل. |
| إعادة التحميل دون اتصال تعرض صفحة خطأ | لم يُفتح التطبيق وهو متصل أولاً، أو أن service worker غير فعّال. اتصل بالإنترنت، وافتح التطبيق، وانتظر بضع ثوانٍ (تحقق من **Application ← Service Workers**)، ثم أعد الاختبار. |
| حاوية بحالة `unhealthy` | نفّذ `docker compose logs backend` (أو `db` أو `frontend`) واقرأ آخر الأسطر. |

## ٩. محتويات الحزمة

```
muhaid_company/
├─ README.md / README.ar.md   هذا الدليل (إنجليزي / عربي)
├─ docker-compose.yml    db + backend + frontend (+ tools للترحيل وإنشاء المسؤول)
├─ .env                  إعدادات تجريبية (لا أسرار حقيقية)
├─ sample-photo.jpg      صورة لإرفاقها بتفتيش تجريبي
├─ muhaid_backend/       واجهة NestJS + Drizzle ORM + PostgreSQL (يحوي Dockerfile)
│   └─ docs/API.md       وصف الواجهة البرمجية
└─ muhaid_frontend/      تطبيق React + TypeScript + Vite PWA (يحوي Dockerfile و nginx.conf)
```

- الواجهة الخلفية: NestJS 12 وDrizzle ORM وPostgreSQL ورمز JWT (Bearer) ورفع الصور مع فحص نوع الملف.
- الواجهة الأمامية: React 19 وTanStack Query (تُحفظ ذاكرة التخزين المؤقت على الجهاز) وDexie / IndexedDB (الصادر دون اتصال) وservice worker للتحميل دون اتصال، مع العربية والإنجليزية ودعم الاتجاه من اليمين إلى اليسار.
- Docker: بناء متعدد المراحل. تعمل صورة الواجهة الخلفية بمستخدم غير جذري، وصورة الواجهة الأمامية صغيرة تقدّم الملفات المبنية عبر nginx.

## ١٠. إيقاف الحاويات

نفّذ الأمر التالي داخل مجلد المشروع (الذي يحوي `docker-compose.yml`):

```
docker compose down
```

يوقف هذا الأمر الحاويات ويحذفها مع الشبكة، و**تبقى بياناتك** محفوظة في وحدة تخزين قاعدة البيانات، فيبدأ `docker compose up -d` التالي بالبيانات نفسها.

لإيقاف الحاويات دون حذفها استخدم `docker compose stop`. ولحذف كل شيء بما فيه جميع البيانات استخدم `docker compose down -v`، ولا يمكن التراجع عنه.
